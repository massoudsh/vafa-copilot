# Wiki Schema — قوانین این ویکی

> این ویکی کنار کد نگه‌داری می‌شود و باید **هر بار که پروژه توسعه پیدا می‌کند** به‌روز بماند
> (feature جدید، endpoint جدید، rule جدید در موتور تصمیم، تغییر ساختار داده).

## ساختار پوشه

```
docs/wiki/
  schema.md      # همین فایل — قوانین
  overview.md    # یک‌نگاه کلی پروژه (≤۴۰۰ کلمه)
  index.md       # کاتالوگ همه صفحات، گروه‌بندی‌شده
  log.md         # تاریخچه append-only تغییرات (جدیدترین در بالا)
  entities/      # هر entity مهم یک صفحه (موتور، API، مدل داده، لندینگ‌پیج)
  concepts/      # flowها، تصمیم‌های معماری، قراردادها
```

## شروع هر بار کار روی این پروژه
1. اول `overview.md` و `index.md` بخوانید.
2. فقط صفحات مرتبط با کار فعلی را باز کنید.

## وقتی کد تغییر کرد — قانون اکید
هر بار که فایلی در `mvp/`, `landing/`, `docs/architecture.md` یا `README.md` تغییر معنایی می‌کند:
1. مشخص کنید کدام entity/concept تحت تأثیر است.
2. همان صفحه را به‌روز کنید (فیلد جدید، endpoint جدید، rule جدید، dependency جدید).
3. اگر entity/concept کاملاً جدید است، صفحه جدید بسازید و در `index.md` لینک بدهید.
4. یک خط در `log.md` اضافه کنید: `## [YYYY-MM-DD] update | <خلاصه>`.

تغییرات جزئی (typo، فرمت) نیاز به آپدیت ندارند.

## لینک‌گذاری (Obsidian/GitHub-wiki style)
- `[[entities/next-best-action-engine]]` بدون پسوند `.md`.
- نام فایل‌ها: lowercase + hyphen.

## ساختار صفحه‌ی entity
```markdown
# {نام}

> یک‌خطی توضیح هدف.

## مسئولیت‌ها
- ...

## وابستگی‌ها
- [[concepts/xxx]] — چرا

## قراردادها / Edge cases
- ...

## منابع کد
- `path/to/file.py:42` — توضیح
```
